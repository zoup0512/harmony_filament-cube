# 还原成功结算卡片：实现与验证

日期：2026-10-28

## 结论

普通计时挑战和进阶教学还原成功后，原先只在操作区下方显示一行文字，小屏需要向下滚动才能看到。本次新增一个居中的原生模态结算卡片，让完成反馈始终可见。

界面按最终确认的范围保持极简，只有三项内容：成功标题、魔方阶数（教学另有当前关卡）、深色成绩卡内的用时与步数。没有图标、关闭按钮、说明文字或“下一关／再来一局”按钮。点击卡片外遮罩或按系统返回键关闭，关闭后保留已还原魔方和页面上的成绩。成绩保存、教学进度和提示辅助规则没有改变。

## 实现要点

- 卡片由 `CustomDialogController` 承载，属于系统对话框层，不放在游戏页面的 `Scroll` 或页面 `Stack` 内，因此不受滚动位置和组件层级影响。
- 最后一步转动提交、计时冻结并绘制完成态之后立即展示，不等待本地存储；存储结果不改变卡片内容。
- 本局数据放入独立的 `@Observed` 快照，对话框以 `@ObjectLink` 引用，避免绑定到仍在变化的游戏计数器。
- 同局只创建一次对话框：关闭、切后台再回来、保存回调、重绘和重复完成判定都不会重新弹出；旧局快照的关闭回调不能关闭或打断新局。
- 卡片显示期间吞掉背景触摸与转层请求；遮罩点击和系统返回通过 `onWillDismiss` 统一关闭。
- `resetSession`、页面销毁会释放对话框；自由练习、自动复位和五步入门教程不触发结算。
- 中文成功标题使用半角 `!`，消除全角标点右侧留白导致的视觉偏左。

## 设备验证

设备为本机已有的 Pura90 模拟器，HarmonyOS 6.1.1 / API 24，1320 × 2856，密度 560，简体中文。全部通过实际页面点击和魔方表面滑动触发，没有注入完成状态，也没有为验证添加生产调试入口。

1. 教学第一关以 `R'` 完成，卡片显示“独立通关”、`2 × 2 魔方 第 1 关`、用时和步数；布局中卡片内只有这 7 个文本，没有按钮或装饰。
2. 点击卡片外背景的“目标”按钮位置，只关闭卡片，不穿透触发目标弹窗，用时不变。
3. 重试再次通关后按系统返回键，卡片关闭且仍停留在已还原页面。
4. 普通二阶随机打乱后沿真实还原提示逐步手势还原，显示“还原成功”与辅助局成绩，页面提示仍说明本局不记录成绩。
5. 此前版本还验证了退到系统桌面再返回不重弹、教学“下一关”和新纪录显示；这些元素在最终极简版本中已移除。

标题中心线核对：修复前两行可见字形中心相差 31.5 个物理像素，改用半角 `!` 后相差 1 个像素（659 与 660），未添加固定偏移。

## 验证边界

- 未连接实体手机，界面验收基于 HarmonyOS 模拟器。
- 未在设备上切换英文、超大字号或其他屏幕规格；多语言与自适应结构由自动化测试覆盖，不能替代这些配置的实机截图。
- 未强制制造存储写入失败、其他阶数或末关的卡片展示；这些路径由逻辑测试覆盖。
- 没有修改成绩存储格式，没有清空应用数据或已有成绩；模拟器验收新增了教学通关进度。
- 截图、布局抓取和日志保留在本地，不纳入 Git；探测脚本 `device-probe.mjs` 依赖本次设备状态，仅作手动排查工具，不是自动验收套件。
